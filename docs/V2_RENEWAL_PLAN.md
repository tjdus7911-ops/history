# V2 구현·검수 계획

기준 main: `92bd615daed24dbd021f9d33c9c8a3c68b859f75`.

## 기존 구조

- 정적 HTML/CSS/JavaScript 앱. `dist/index.html`의 데이터 → 챕터 확장 → 검증 기출 → 배경/문제 보정 → `app.js` 순서로 실행한다.
- 고려 CH.01–12 구현. 조선/대한제국/일제강점기/대한민국은 준비중이다.
- 저장 키 `lived-history-v1`, SAVE_VERSION 15. run/mainRun, 재플레이, 챕터 해금, 대화 커서, 선택지, 문제 큐와 누적 기록을 보존한다.
- 캐릭터 초상 250개 등록, 배경 100개 등록. 초상 ID 여러 개가 실제 같은 파일을 공유한다. 실제 등장 표정·나이·복장별로 대체 아트를 연결하되 ID를 유지한다.
- 실제 기출 등록 55개, 원본 이미지 연결 51개. 4개는 이전 원본 미확인 상태로 실제 기출 UI가 표시되지 않는다. 추가 원본 확보 여부를 재조사한다.
- 기존 누적 정답/오답 횟수는 있으나 모든 풀이의 날짜는 없다. V2 날짜별 지표에 과거 날짜를 추정해 넣지 않는다.

## 구현 순서

1. 기존 장면·대사·분기·문제·저장 데이터를 기준 스냅샷으로 보관한다.
2. 별도 V2 표시 계층으로 홈/학습/오답노트/내 기록을 변경한다. 기존 진행 동작을 재사용한다.
3. 실제 풀이 시각을 누적 기록에 추가한다. 날짜가 없는 과거 기록은 누적 통계에만 반영한다.
4. 문제 회상은 실제 relatedSceneId 배경으로 통일한다. 오답 관련 스토리는 미리보기로 열어 현재 run을 바꾸지 않는다.
5. 레퍼런스의 2D 캐릭터·배경을 제작하고 기존 ID에 연결한다. 연의 남성 설정, 도윤의 노화와 주인공의 비노화를 유지한다.
6. 보관 PDF와 정답표를 대조해 이미지·정답·출처를 검증하고, 각 챕터에서 학습한 개념 직후 실제 기출을 연결한다.
7. 데이터 보존, 모든 챕터 도달성, 저장/재플레이, 모바일 화면과 실제 정답/오답/스토리 복귀를 검사한다.
8. npm test/build, 변경 범위·출처·용량 보고서를 확인한 뒤 main에 commit/push한다.

이 문서는 진행 계획이며 최종 완료 보고서는 별도로 기록한다.
