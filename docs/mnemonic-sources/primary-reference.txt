[눈떠보니 한국사 - 연상기억법 데이터 전면 재구축 / 확정 기준 목록 제공]

이번 작업에서는 AI가 연상기억법을 새로 만들어내지 마세요.

제가 첨부한 원본 스크린샷에서 사람이 직접 확인한
'실제 암기 문장' 목록을 아래에 제공합니다.

이 목록이 이번 작업의 PRIMARY REFERENCE입니다.

기존 구현처럼

광종의 왕권 강화
→ 노비안검법
→ 과거제
→ 공복 제정

을 하나의 연상기억법으로 만드는 것은 잘못된 구현입니다.

'광종의 왕권 강화'는 역사 개념 제목이지 mnemonic이 아닙니다.

이번 작업의 핵심은

[주제]
+
[실제 암기 문장]
+
[암기 문장의 cue]
+
[cue가 가리키는 역사 항목]

을 정확하게 연결하는 것입니다.


==================================================
A. 절대 규칙
==================================================

1. 아래 제공한 mnemonic을 임의로 역사 요약문으로 바꾸지 마세요.

2. AI가 새로운 mnemonic을 만들어
   원자료에 있었던 것처럼 등록하지 마세요.

3. title과 mnemonic은 별개입니다.

예:

title = 조선시대 궁궐

mnemonic = 복덕(방) 경희(가) 운(다)


4. mnemonic이 없는 단순 개념 묶음은
   연상기억법 카드로 만들지 마세요.

5. 문장이 이상하고 유치하고 말이 안 되는 것처럼 보여도
   그것이 암기 장치입니다.

6. 괄호 안 글자는 문장을 자연스럽게 만들기 위한 연결어일 수 있습니다.
   실제 cue가 무엇인지 아래 원문 풀이와 대조하세요.

7. OCR이나 이미지 판독이 애매한 항목은
   임의 수정하지 말고 REVIEW_REQUIRED 처리하세요.

8. 아래 목록뿐 아니라 첨부 RAW SOURCE 전체에서도
   동일 구조를 찾아 추가 inventory를 만들 수 있습니다.

단, 자동으로 새 mnemonic을 창작하면 안 됩니다.

==================================================
C. 별도 구조의 연상법
==================================================

위 번호 목록과 별도로
단순 두문자 문장으로 표현되지 않는 자료도 있습니다.

대표적으로 무덤 암기법입니다.

예:

골(식)돌(방)무덤 = 식빵

고구려는 후식으로 식빵 먹음
백제는 사비로 식빵 사먹음
신라는 통후추 식빵 먹음
발해 정혜공주에게 고기식빵을 줌

이런 것은 버리지 마세요.

memoryType을

STORY
WORDPLAY

등으로 분류하여 별도 카드로 만드세요.

따라서 위 111개만 전체라고 단정하지 마세요.

111개는 현재 스크린샷에서 사람이 직접 식별해
정리한 기준 목록입니다.

RAW SOURCE와 이미지 전체에서
추가적인 명확한 mnemonic이 발견되면 inventory에 추가하되,
AI가 새로 창작해서 추가하면 안 됩니다.


==================================================
D. 각 mnemonic의 cue → fact를 반드시 구축
==================================================

문장만 저장하면 안 됩니다.

예:

title:
조선시대 궁궐

mnemonic:
복덕(방) 경희(가) 운(다)

facts:
[
  {
    cue: "복",
    title: "경복궁"
  },
  {
    cue: "덕",
    title: "창덕궁"
  },
  {
    cue: "경",
    title: "창경궁"
  },
  {
    cue: "희",
    title: "경희궁"
  },
  {
    cue: "운",
    title: "경운궁"
  }
]


또:

title:
숙종

mnemonic:
화난 숙종은 벌써 3회독

각 cue가 아래 원자료의 어떤 역사 사실을 가리키는지
원문을 대조하여 모두 연결하세요.


==================================================
E. 원자료의 아래 줄을 적극 활용
==================================================

스크린샷에서 파란 mnemonic 아래에 있는 검은 글씨가
대부분 cue에 대응하는 역사 항목입니다.

따라서 AI의 일반 역사 지식으로 추측하지 말고

1. 스크린샷
2. RAW SOURCE
3. repo의 검증된 canonical data

순서로 대조하세요.

원문 판독이 애매하면 REVIEW_REQUIRED입니다.


==================================================
F. 역사 검증과 원문 보존을 분리
==================================================

원자료의 mnemonic은 SOURCE로 보존합니다.

그러나 아래 역사 항목에 오타/OCR 오류/사실 오류가 있을 수 있으므로
production 공개 전 검증합니다.

필요한 경우:

originalMnemonic
publicMnemonic
sourceFacts
verifiedFacts

를 분리하세요.

AI가 원문의 암기문구를 마음대로 예쁜 문장으로
재작성하지 마세요.


==================================================
G. 유형 분류
==================================================

연상기억법은 상위 기능입니다.

각 카드에는 memoryType을 둡니다.

- 두문자
- 문장연상
- 말장난
- 순서연상
- 숫자연상
- 스토리연상
- 리듬연상
- 비교연상

하나의 mnemonic에 여러 성격이 있으면
primaryMemoryType + tags 형태로 관리해도 됩니다.

N. 저작권/표현 검토
==================================================

원문 데이터에는 정확히 보존하되
필요하면 REVIEW_REQUIRED 처리합니다.

또 욕설/성적 표현/비하 표현 등은:

originalMnemonic
publicMnemonic
moderationStatus

로 분리하세요.

다만 publicMnemonic을 만들 때도
cue 구조가 완전히 사라지는 일반 역사 문장으로 바꾸지 마세요.


==================================================
O. 기존 잘못된 데이터 전수 제거/교체
==================================================

현재 연상기억법 DB 전체를 검사합니다.

다음 조건이면 잘못된 카드입니다.

mnemonic === title

또는

mnemonic이 단순 역사 제목

또는

실제 기억 장치가 존재하지 않음


예:

광종의 왕권 강화
→ 광종의 왕권 강화

삭제/교체 대상입니다.


RAW SOURCE에 대응 mnemonic이 있으면
그 mnemonic으로 교체하세요.

S. 중요한 수량 검증
==================================================

사람이 이미지에서 직접 확인한 기준 mnemonic이
최소 111개입니다.

따라서 결과가:

10개
20개
30개

등으로 나오면 작업 완료가 아닙니다.

파싱 실패입니다.

최소 기준 목록 111개를 inventory에서 모두 추적해야 합니다.

단, 애매한 항목은 억지로 PUBLISHED하지 말고
REVIEW_REQUIRED로 유지하면 됩니다.
